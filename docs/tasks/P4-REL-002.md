إضافة واجهة تجريبية مستقلة على نفس أصل Studio5 تتيح للمستخدم تنزيل Backup كامل، اختيار Backup من
الجهاز، فحصه، ثم استعادته بعد تأكيد صريح.

## النطاق

- Route مستقلة: `/reliability/`.
- فتح نفس IndexedDB ومخزن المحتوى المستخدمين في Library.
- عرض ملخص البيانات الحالية.
- إنشاء وتنزيل ملف `.studio5-backup.json`.
- منتقي ملف أصلي ظاهر ومتوافق مع MatePad.
- فحص الملف قبل تفعيل الاستعادة.
- عرض Manifest: التاريخ، Schema، عدد الكيانات، عدد الملفات/Ink، والحجم.
- Checkbox تأكيد إلزامي قبل استبدال البيانات.
- Reload بعد الاستعادة حتى تعيد كل الوحدات فتح Repository من البيانات الجديدة.
- لا قفل، لا تشفير، لا Cloud، لا Merge تلقائي.

## Replace / Retire

الواجهة `Experimental`. يمكن استبدالها أو إخفاؤها من دون تغيير تنسيق Backup أو حذف البيانات؛ العقود
داخل `packages/studio5-core/src/backup.mjs`.

## حد النشر التجريبي الحالي

Route الجديدة تعمل على أصل موقع Lecture/Library نفسه، لذلك تصل إلى PDF وNotes وبيانات Core الموجودة
في هذا الموقع. موقع Ink Lab القديم منشور على أصل مختلف ويستخدم IndexedDB مختلفاً؛ المتصفح يمنع قراءة
بياناته مباشرة من Route الحالية. محرك Core نفسه يثبت Backup/Restore لـInk، لكن دمج بيانات الموقعين
التجريبيين يحتاج مهمة Namespace/Consolidation مستقلة قبل الاعتماد الجامعي الحقيقي.

لا يجوز وصف النسخة المنشورة الحالية بأنها Backup للموقعين معاً. بيانات Ink Lab القديمة لا تُحذف،
وتبقى قابلة للوصول من موقعها إلى أن تُعتمد خطة نقل صريحة.

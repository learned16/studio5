## داخل النطاق

- `resolveLectureCaptureAsTask`: ينشئ Task وResolution معاً أو لا ينشئ أياً منهما.
- سياق Task مشتق من Lecture، وليس من اسم مادة أو إدخال عميل غير موثوق.
- إعادة المحاولة بعد Recovery لا تنشئ Task مكررة.
- Inbox projection نقي يعمل محلياً ولا يضيف Collection مشتقة.
- Inbox يعرض:
  - Captures التي لا تملك Resolution.
  - Captures التي Resolution الخاصة بها تحمل outcome=`inbox`.
- فلاتر Inbox حسب Lecture أوSubject عبر Stable IDs.

## خارج النطاق

- واجهة Inbox أو Capture.
- إشعارات أو مزامنة.
- Search العام وFavorites/Recent.
- PDF وAI.
- إنشاء أنواع كيانات أخرى من Capture.

## معايير القبول

1. Task وResolution يحفظان في Snapshot واحد.
2. فشل Commit يبقي Journal قابلة للاستعادة ولا يترك Task وحيدة.
3. إعادة نفس الطلب بعد Recovery تعيد النتيجة الموجودة ولا تنشئ تكراراً.
4. Task تأخذ `subjectId` و`lectureId` من Lecture المرتبطة بالـCapture.
5. Inbox لا يغير Snapshot ولا يحتاج شبكة أو Schema جديد.
6. Inbox يعرض غير المنظم والمحفوظ عمداً في Inbox فقط.
7. الفلاتر والترتيب حتمية ومختبرة.
8. كل اختبارات Core واختبارات Ink regression تنجح.

## Rollback

إزالة API التحويل وملف Inbox واختباراته. تبقى Captures/Closeouts/Resolutions وSchema v5 كما هي، ولا تحذف أي بيانات.

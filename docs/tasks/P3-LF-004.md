## داخل النطاق

- صفحة `/closeout/` على نفس أصل Capture ونفس IndexedDB.
- بدء Closeout أو استئناف الموجود بصورة idempotent.
- عرض Captures الخام من المحاضرة الحالية.
- Resolution لكل Capture:
  - تحويل ذري إلى Task.
  - Review.
  - إبقاء في Inbox.
  - Answered.
  - Dismissed مع بقاء Capture الخام.
- عنوان Task وأولوية وموعد اختياري.
- Progress واضح ومنع الإكمال قبل حسم جميع Captures.
- Summary اختياري وإكمال Closeout.
- عمل Local-first ومن دون شبكة بعد أول فتح.
- نشر نسخة خاصة محدثة على موقع Lecture Capture نفسه.

## خارج النطاق

- تعديل Capture الخام أو حذفه.
- إعادة فتح Closeout مكتمل أو إنشاء Closeout ثانٍ للمحاضرة نفسها.
- Search وFavorites/Recent وPDF وAI.
- مزامنة متعددة الأجهزة.
- تغيير P0 Ink.

## معايير القبول

1. الصفحة تقرأ Captures المسجلة من صفحة Capture على الأصل نفسه.
2. بدء Closeout المتكرر لا ينشئ تكراراً.
3. كل Resolution تحفظ محلياً وترتبط بالـCapture والـCloseout الصحيحين.
4. تحويل Task ذري ويحمل سياق Subject/Lecture الموثوق.
5. Capture الخام يبقى موجوداً بعد أي Resolution.
6. لا يكتمل Closeout بوجود Capture غير محسوم.
7. الصفحة تميز المكتمل من غير المكتمل بعد إعادة الفتح.
8. Build وLint وType Check واختبارات الواجهة وCore وInk regression تنجح.
9. الفرع مستقل ولا يدمج في `main`.

## Replace / Retire

- يمكن استبدال مجلد `closeout/` بالكامل مع إبقاء Core وCaptures وResolutions.
- تقاعد الواجهة يزيل رابطها وصفحتها فقط، ولا يحذف البيانات.
- أي تغيير لمعاني Outcomes يحتاج Change Control وMigration/Recovery.

## Rollback

إزالة مجلد `closeout/` ورابط الانتقال وملفات Cache الخاصة به. تبقى جميع بيانات Core كما هي ولا تنفذ عملية حذف.

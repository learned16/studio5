# P4-REL-003 — Browser Storage Namespace Consolidation

## الحالة

`IMPLEMENTED / VERIFIED / DEPLOY PENDING`

## الهدف

توحيد هوية مخازن Studio5 داخل أصل Lecture/Library/Reliability الحالي، مع نقل آمن
للبيانات الموجودة تحت أسماء Phase 3 القديمة، ومنع كل واجهة جديدة من اختراع أسماء
IndexedDB خاصة بها.

هذه المهمة لا تعيد بناء Backup/Restore، ولا تحذف بيانات Ink Lab القديم الموجود على
أصل مختلف.

## المشكلة المثبتة

- Ink Core يستخدم `studio5-core` و`studio5-file-content`.
- Lecture/Library/Reliability تستخدم `studio5-p3-lecture-capture-core` و
  `studio5-p3-library-content`.
- المتصفح يعزل IndexedDB حسب الأصل؛ لذلك Ink Lab القديم لا يمكن قراءته مباشرة من
  موقع Lecture/Library.
- تغيير الاسم مباشرة سيُظهر مخزناً فارغاً ويعطي انطباعاً خاطئاً بفقد البيانات.

## النطاق

1. تعريف Storage Profile مركزي وثابت الإصدار داخل Core.
2. تعريف الأسماء المعتمدة والأسماء القديمة المعروفة.
3. إضافة مهاجرة idempotent تنسخ Snapshot/Journal ومحتوى الملفات من الاسم القديم
   إلى الاسم المعتمد، بعد فحص التعارضات.
4. عدم استبدال مخزن معتمد غير فارغ تلقائياً.
5. عدم حذف أو تعديل المخزن القديم بعد النقل.
6. ربط Lecture/Library/Reliability بالعقد الموحد.
7. توفير نتيجة مهاجرة قابلة للعرض والتسجيل والاختبار.

المخازن القديمة لا تُحذف. الرجوع عن الكود يعيد Runtimes إلى الأسماء السابقة، وتبقى
النسخة المنقولة في المخازن المعتمدة غير مرتبطة بأي حذف تلقائي. أي تنظيف مستقبلي
يحتاج مهمة منفصلة وموافقة صريحة.

# P4-REL-001 - Portable Backup / Restore Core

## الهدف

إنشاء محرك محايد عن الواجهة يصدر نسخة احتياطية كاملة من Studio5، ويتحقق منها، ثم يستعيدها من دون
فقد بيانات أو دمج صامت. تشمل النسخة Snapshot الحالي وكل محتوى PDF/الملفات وInk المشار إليه في البيانات.

## النطاق

- تنسيق Backup محمول ومُرقّم الإصدار.
- Manifest يحصي Schema والكيانات والمحتوى والحجم.
- تضمين Snapshot الحالي مع bytes الملفات وInk مرة واحدة لكل storage key.
- فحص الحجم وSHA-256 والعلاقات قبل قبول النسخة.
- استعادة آمنة وقابلة لإعادة المحاولة.
- رفض استبدال بيانات موجودة ما لم يمرر المستدعي موافقة صريحة.
- استخدام Journal/Recovery الحالي عند حفظ Snapshot المستعاد.
- لا واجهة، ولا Cloud، ولا Sync، ولا Auto-merge في هذه المهمة.

## العقود

- `createPortableBackup({ snapshot, contentStore, now })`
- `verifyPortableBackup(bundle)`
- `restorePortableBackup({ bundle, database, contentStore, allowReplace })`
- `AcademicRepository.createPortableBackup()`

يكون التنسيق JSON-safe في هذه الدفعة حتى يمكن تنزيله ورفعه من الويب لاحقاً. تُحوّل bytes إلى Base64
داخل الحزمة، ولا تُخزن الحزمة تلقائياً داخل IndexedDB.

## قواعد السلامة

1. لا تُقرأ محتويات لا يشير إليها `FileVersion` أو `InkRevision`.
2. يُرفض Backup إذا كان محتوى مشار إليه مفقوداً أو تالفاً.
3. يُرفض Restore إذا اختلف الحجم أو SHA-256 أو Storage Key أو Manifest.
4. الاستعادة إلى بيانات غير فارغة تحتاج `allowReplace: true`.
5. لا يوجد Merge تلقائي في هذه المهمة.
6. تكتب bytes كـcontent-addressed immutable records قبل حفظ Snapshot.
7. إذا فشل حفظ Snapshot، تبقى Journal للاستعادة ولا تُحذف البيانات الحالية صمتاً.

## معايير القبول

- [x] Backup فارغ صالح وله Manifest مفهوم.
- [x] Backup كامل يحفظ Snapshot وPDF وInk بلا تكرار bytes.
- [x] التصدير لا يغيّر Snapshot أو bytes الأصل.
- [x] فحص Backup يكشف تعديل Snapshot أو bytes أو الحجم أو manifest.
- [x] Restore إلى مخزن فارغ يعيد العدّ والروابط وbytes نفسها.
- [x] Restore يرفض استبدال بيانات موجودة بدون موافقة صريحة.
- [x] Restore مع الموافقة الصريحة يحفظ Backup السابق كما هو.
- [x] فشل Commit يبقي Recovery Journal ويمكن الاستكمال بلا فقد.
- [x] اختبارات Core والانحدار للقلم وPhase 3 ناجحة.

## خارج النطاق

- كلمة مرور أو تشفير Backup.
- اختيار مكان التخزين.
- واجهة تنزيل/رفع النسخة.
- Backup تلقائي مجدول.
- Cloud Sync أو حل تعارض متعدد الأجهزة.
- ضغط ZIP أو Streaming للملفات الكبيرة.

هذه القدرات تُفتح في مهام Phase 4 مستقلة بعد ثبوت صحة المحرك.

## Rollback / Recovery

لا تغيير Schema في هذه المهمة. الرجوع إلى `codex/p3-native-pdf-picker` يزيل المحرك فقط ولا يغيّر
بيانات المستخدم. أي bytes أضيفت أثناء Restore فاشل تبقى immutable وغير مرتبطة حتى إعادة المحاولة،
ولا يُحذف منها شيء تلقائياً.

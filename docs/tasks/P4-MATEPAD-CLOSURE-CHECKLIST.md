# Phase 4 — MatePad Closure Checklist

**GitHub-connected preview URL:** `PENDING`

**مصدر النسخة المطلوبة:** Build حقيقي ناتج من branch داخل مستودع GitHub.

**النتيجة:** `BLOCKED — GITHUB-CONNECTED PREVIEW PENDING`

لا تُستخدم ChatGPT Sites أو Sites v9 لإغلاق المرحلة الرابعة. يبقى Device Gate
محجوباً إلى أن تتوفر معاينة مرتبطة مباشرةً بفرع GitHub وتعرض الـcommit المختبر
نفسه. لا تنشئ هذه المهمة Cloudflare أو Vercel deployment.

نفّذ الاختبار على بيانات تجريبية يمكن استبدالها. لا تستخدم النسخة الوحيدة من ملف
دراسي مهم في تجربة الاستعادة.

## قبل البدء

- [ ] تأكد أن رابط المعاينة مرتبط بفرع GitHub ويعرض الـcommit المطلوب اختباره.
- [ ] افتح GitHub-connected preview على MatePad نفسه.
- [ ] تأكد أن الاتصال مستقر وقت تنزيل ملف الـBackup.
- [ ] سجّل عدد ملفات PDF والملاحظات والرسومات الحالية.

## PDF وStorage Migration

- [ ] افتح PDF حقيقياً من `/library/`.
- [ ] تنقّل بين صفحتين على الأقل.
- [ ] جرّب Zoom In وZoom Out ثم Fit.
- [ ] تأكد أن PDF والملاحظات القديمة ظاهرة بعد Storage migration.
- [ ] أعد تحميل الصفحة وتأكد أن البيانات لم تتكرر.

## Backup وRestore

- [ ] افتح `/reliability/`.
- [ ] أنشئ Backup ونزّله إلى الجهاز.
- [ ] افحص الـBackup من الواجهة وتأكد أن التحقق ينجح.
- [ ] أضف بعد التنزيل PDF أو Note أو Ink تجريبياً جديداً يمكن فقده.
- [ ] اختر ملف الـBackup القديم واضغط فحص.
- [ ] وافق صراحةً على الاستعادة بعد ظهور ملخص الملف الصحيح.
- [ ] تأكد أن PDF وNotes وInk الموجودة وقت إنشاء الـBackup رجعت.
- [ ] تأكد أن البيانات الجديدة المضافة بعد الـBackup لم تختلط بالنسخة المستعادة.

## إعادة الفتح وعدم التكرار

- [ ] أغلق الموقع أو التطبيق بالكامل.
- [ ] افتحه من جديد.
- [ ] تأكد أن PDF وNotes وInk المستعادة ما زالت موجودة.
- [ ] أعد تحميل الموقع مرة ثانية لتشغيل مسار migration مرة أخرى.
- [ ] تأكد أن أعداد البيانات لم تتضاعف ولا توجد نسخ مكررة.

## التقرير

- [ ] `PASS`: كل البنود نجحت بلا فقد أو تكرار.
- [ ] `FAIL`: اذكر البند، ما ظهر، وهل بقي ملف الـBackup قابلاً للفتح.

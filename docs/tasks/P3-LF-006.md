# P3-LF-006 - Durable Offline Operation Queue

## الهدف

إنشاء طابور عمليات محلي دائم وواضح الحالات ليحفظ الأعمال التي تحتاج إرسالاً لاحقاً، من دون بناء مزامنة سحابية في Phase 3.

## المتطلبات المرتبطة

- `S5-NFR-OFFLINE-001`
- المرجع السلطوي: `offline queue` في Phase 3، مع عمل محلي لا يعتمد على الإنترنت.

## النطاق

- `OfflineOperation` عام بمعرف ثابت و`idempotencyKey`.
- الحالات: `pending`, `processing`, `succeeded`, `failed`, `conflict`.
- Enqueue ذرية لا تكرر العملية نفسها.
- Claim للعملية التالية حسب `availableAt`.
- نجاح وفشل وتعارض وإعادة محاولة يدوية.
- استعادة عملية بقيت `processing` بعد انقطاع أو إغلاق.
- Schema v7 ومهاجرة v6 -> v7 مختبرة بلا فقد.
- Repository APIs محلية فقط.

## خارج النطاق

- لا مزود Sync ولا Backend ولا حساب مستخدم.
- لا رفع ملفات إلى الإنترنت.
- لا حل تعارض تلقائي؛ حالة `conflict` تحفظ الدليل لـPhase 4.
- لا واجهة مستخدم في هذه الدفعة.

## قواعد السلامة

- Payload metadata فقط؛ لا تُنسخ bytes الملفات أو Ink داخل Snapshot.
- لا حذف تلقائي لعملية ناجحة أو فاشلة.
- كل انتقال حالة صريح ومختبر.
- `entityId` Stable ID ولا يعتمد على اسم المادة.

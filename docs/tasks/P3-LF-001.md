## حدود الوحدة

- `LectureCapture`: تسجيل سريع غير متلف مرتبط بمحاضرة عبر Stable ID.
- `LectureCloseout`: جلسة تنظيم واحدة لكل محاضرة.
- `CaptureResolution`: قرار ثابت يربط Capture بـCloseout، وبمهمة موجودة عند اختيار `task`.
- أنواع Capture العامة: ما فهمت، مهم، تكليف، سؤال للأستاذ، ملاحظة أستاذ.
- كل البيانات محلية وتدخل Schema v5 بمهاجرة مستقلة من v4.

## خارج النطاق

- واجهة Capture أو Closeout.
- PDF/annotations.
- Unified Inbox وSearch وFavorites/Recent.
- إنشاء Task تلقائياً من Capture؛ يدخل بدفعة مستقلة حتى يكون التحويل ذرياً ومختبراً.
- Understanding Rescue أو AI.
- تعديل أي ملف من واجهة Ink المنشورة.

## معايير القبول

1. Migration v4 -> v5 تضيف مجموعات Lecture Flow فارغة وتحفظ كل بيانات Phase 2 كما هي.
2. Capture يرتبط بمحاضرة موجودة ولا يثبت اسم مادة.
3. يوجد Closeout واحد فقط لكل محاضرة، وبدؤه idempotent.
4. Resolution يرتبط بـCapture وCloseout من المحاضرة نفسها.
5. نتيجة `task` تحتاج Task موجودة ومرتبطة بالمحاضرة نفسها.
6. لا يكتمل Closeout قبل وجود Resolution لكل Captures التابعة للمحاضرة.
7. Raw Captures وResolutions غير قابلة للاستبدال أو الحذف الصامت.
8. Reopen وRecovery وConcurrent writes لا تفقد السجلات.
9. Lint وType Check وكل الاختبارات تنجح.

## Rollback / Recovery

لا تعاد كتابة Migration v4. قبل اعتماد v5 يمكن الرجوع إلى فرع Phase 2. بعد وجود بيانات v5 يكون الرجوع عبر Export/Restore أو Migration لاحقة؛ لا تحذف Collections الجديدة ولا Revisions القديمة.

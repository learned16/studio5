## Change Ledger

### CL-001 - تنظيم حزمة التعاون الجديدة

- **التغيير:** دمج المحتوى الفريد في وثائق حالية وإضافة SOP وTraceability وReviewer Guide وقالب PR.
- **السبب:** الحزمة الأصلية تحتوي تكراراً وقرارات تعود لمرحلة ما قبل البناء.
- **الأثر:** تحسين تعاون عدة وكلاء من دون تغيير كود التطبيق أو نطاق السنة الأولى.
- **البدائل:** نسخ الحزمة كما هي، أو إبقاؤها مضغوطة. رُفضا بسبب التعارض والازدواجية.
- **القرار:** Approved بطلب المستخدم: “اعمل طريقتك بس لا تخلي الملف مضغوط رتبه”.

### CL-002 - سياسة التجارب القابلة للاستبدال

- **التغيير:** فرض فصل دائم بين Core/Domain وAdapter/Bridge وPrototype UI والنشر، مع حالة نضج لكل تجربة.
- **السبب:** العمل الحالي يختبر احتياجات افتراضية قبل بدء الدوام، وقد يكشف الاستخدام الحقيقي أن ميزة أو شكل واجهة ضعيف أو غير مفيد.
- **الأثر:** زيادة بسيطة في عدد الملفات والفروع مقابل إمكانية تعديل أو استبدال تجربة من دون هدم Studio5 أو فقد البيانات.
- **البدائل:** بناء واجهة موحدة مترابطة الآن، أو اعتبار كل Prototype شكلاً نهائياً. رُفضا لأنهما يرفعان كلفة التعديل بعد بدء الدراسة.
- **القرار:** Approved بقرار المستخدم بتاريخ 2026-07-26.

### CL-003 - نتيجة Gate 0 وتوصية Stack

- **التغيير المقترح:** اعتماد Web/PWA لواجهة السنة الأولى ومحرك Ink الحالي.
- **السبب:** نجاح الضغط وPalm rejection والممحاة وRecovery وجلسة 15 دقيقة وقرابة 1000 stroke على MatePad الحقيقي.
- **الأثر:** استمرار البناء فوق Prototype مثبت، مع بقاء Core والبيانات منفصلة وقابلة للترقية.
- **البدائل:** Kotlin/Native، Flutter، أو Native wrapper لاحقاً.
- **القرار:** Approved بموافقة المستخدم الصريحة بتاريخ 2026-07-25؛ أصبحت `ADR-008` بحالة `Adopted`.

### CL-004 - استمرار Phase 3 قبل نتيجة بوابة Notebook/Revisions

- **التغيير:** إلغاء منع بدء Phase 3 الوارد مؤقتاً في ملف مصالحة Gate 0.
- **السبب:** المستخدم أكد أن المراحل مفصولة، وطلب إكمال Phase 3 وإرسال نتيجة جهاز Phase 2 لاحقاً.
- **الأثر:** يستمر P3-LF-004 في مجلد وفرع مستقلين؛ لا تتغير واجهة Ink أو بيانات Notebook.
- **البدائل:** إبقاء Phase 3 متوقفاً حتى وصول النتيجة. تجاوزه قرار المستخدم الأحدث.
- **القرار:** Approved بقرار المستخدم بتاريخ 2026-07-27.

### CL-005 - إغلاق بوابة Notebook/Revisions

- **التغيير:** تحويل P2-GATE-001 وP2-GATE-002 من `DEVICE PENDING` إلى `DONE / DEVICE PASS`.
- **السبب:** أكد المستخدم نجاح البنود الثمانية على MatePad.
- **الأثر:** لا تبقى بوابة وظيفية معلقة في Phase 2، مع بقاء Hardening واختبارات الرجوع المستقبلية.
- **البدائل:** إبقاء الحالة معلقة رغم وجود نتيجة الجهاز. رُفض لأنه يخالف الدليل الأحدث.
- **القرار:** Approved بإفادة المستخدم بتاريخ 2026-07-27.

### CL-006 - توحيد هوية تخزين المتصفح

- **التغيير:** ربط Lecture وLibrary وReliability بأسماء التخزين المركزية وإضافة مهاجرة آمنة من أسماء Phase 3 القديمة.
- **السبب:** منع ظهور بيانات متفرقة أو فارغة بين الواجهات، وجعل Backup/Restore يعمل فوق هوية واحدة.
- **الأثر:** تُنسخ البيانات القديمة دون حذف المصدر؛ يتوقف النقل عند وجود تعارض ولا يستبدل بيانات المستخدم بصمت.
- **البدائل:** إبقاء أسماء مستقلة لكل Prototype، أو تغيير الاسم بلا مهاجرة. رُفضا لأنهما يجزئان البيانات أو يوهمان بفقدها.
- **القرار:** Adopted برمجياً في P4-REL-003؛ ينتظر اختبار MatePad بعد النشر.

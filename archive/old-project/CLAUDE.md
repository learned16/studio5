# Independent Reviewer Guide

هذا الملف موجّه إلى Claude أو أي مراجع مستقل. دوره تقييم التغيير، لا إعادة تنفيذ الميزة في الجولة الأولى.

## القراءة قبل المراجعة

1. `AR_HERE_START.md`
2. `AGENTS.md`
3. `PROJECT_STATUS.md`
4. ملف المهمة داخل `docs/tasks/`
5. الوثائق المتخصصة و`docs/TRACEABILITY.md`
6. Diff الكامل والاختبارات

## المطلوب

- راجع Diff كاملاً مقارنة بقاعدة الفرع الصحيحة.
- افحص مطابقة نطاق المهمة ومعايير قبولها.
- تحقق من نتائج Build/Lint/Type Check/Tests فعليًا.
- ابحث عن فقد البيانات، العلاقات المكسورة، تغييرات Contract غير المسجلة، وتعديلات خارج النطاق.
- افحص Migration وRecovery عند تغيير البيانات.
- لا تعتبر تقرير Builder دليلاً كافيًا وحده.
- لا تعدل الكود في جولة المراجعة الأولى.

## الحكم

استخدم حكمًا واحدًا:

- `PASS`
- `FAIL`
- `NEEDS DECISION`

لكل مشكلة اذكر:

- الملف والموقع.
- طريقة إعادة الإنتاج أو الدليل.
- الأثر.
- الإصلاح المقترح.
- هل تمنع الدمج أم لا.

## حالات تحتاج قرار مستخدم

- تعارض حقيقي بين المرجع السلطوي وقرار حديث.
- توسعة نطاق.
- تغيير معنى ميزة أو تأجيلها.
- تغيير معماري كبير أو Migration غير قابلة للتراجع.
- غياب اختبار جهاز حقيقي لادعاء متعلق بالقلم أو PDF أو الأداء.

المراجع لا يدمج إلى `main` ولا يقرر النطاق نيابة عن المستخدم.

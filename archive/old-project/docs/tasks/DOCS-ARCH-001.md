# DOCS-ARCH-001 - Experimental Modularity Policy

## الهدف

تثبيت قرار المستخدم بأن العمل الحالي قبل بدء الدوام هو اختبار افتراضات، وأن كل قدرة أو واجهة يجب أن تبقى منفصلة وقابلة للتعديل أو الاستبدال أو التقاعد من دون هدم بقية Studio5 أو فقد البيانات.

## المصدر

قرار مستخدم صريح بتاريخ 2026-07-26:

> احنا هسة دا نختبر شي افتراضي... فانت دائما فصل الملفات حتى من نبدي دوام وطلع شي ضعيف او غير مفيد بشكله الحالي نكدر نعدله شلون مانريد.

## الملفات المسموحة

- `AGENTS.md`
- `PROJECT_STATUS.md`
- `docs/ARCHITECTURE_DECISIONS.md`
- `docs/DECISION_LOG.md`

- `docs/tasks/DOCS-ARCH-001.md`

## داخل النطاق

- تعريف حالة الميزة التجريبية.
- فصل Domain/Core عن Adapter/Bridge وعن Prototype UI وعن النشر.
- منع الاقتران المباشر بين واجهات التجارب.
- اشتراط مسار Replace/Retire آمن.
- حماية البيانات عند تغيير شكل الميزة.
- جعل القرار ملزماً لأي وكيل لاحق.

## خارج النطاق

- تغيير أي كود أو Schema.
- حذف أو إعادة تصميم واجهة حالية.
- دمج أي فرع إلى `main`.

## معايير القبول

1. القرار موجود في `AGENTS.md` كقاعدة ملزمة.
2. القرار موثق كـADR وكقرار Adopted.
3. SOP يفرض حدود ملفات ومسار استبدال/تقاعد لكل تجربة.
4. واجهات التجارب لا تصبح مرجعاً نهائياً لمجرد نجاحها تقنياً.
5. تحديث الحالة يوضح أن القرار توثيقي ولا يغير الكود.

## Rollback

إرجاع تعديلات الوثائق في هذا الفرع فقط. لا توجد بيانات أو Schema متأثرة.
